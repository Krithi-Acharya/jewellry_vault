# Jewellry Vault

A Flutter app for cataloguing a wardrobe and jewellery collection, backed by a
Node/Express + Prisma API and a Python worker that auto-categorises uploaded
photos using a vision model.

```
lib/            Flutter app
backend/        Node + Express + Prisma API
python-worker/  Polls for uploaded images and categorises them
```

## Configuration

Nothing in this repo contains real credentials. Each component reads its own
gitignored config file, and each has a committed `.example` alongside it
showing the required keys. To set up your own, copy each example and fill in
your values:

| Component | Copy this | To this | Holds |
|---|---|---|---|
| Backend | `backend/.env.example` | `backend/.env` | `DATABASE_URL`, `PORT`, `CORS_ORIGIN` |
| Worker | `python-worker/.env.example` | `python-worker/.env` | `NVIDIA_API_KEY`, `NVIDIA_MODEL`, `DATABASE_URL` |
| Flutter app | `app_config.env.example` | `app_config.env` | `API_BASE_URL` |

```bash
cp backend/.env.example backend/.env
cp python-worker/.env.example python-worker/.env
cp app_config.env.example app_config.env
```

Each example file documents what its keys mean and where to obtain them. Two
constraints matter most:

- **`DATABASE_URL` must be identical in `backend/.env` and `python-worker/.env`.**
  The backend writes upload jobs and the worker polls for them; if they point at
  different databases, uploaded items stay stuck on the `Uncategorized`
  placeholder because the worker never sees the job.
- **`API_BASE_URL` must match the backend's `PORT`.** Use `http://10.0.2.2:5000/api/v1`
  on an Android emulator — `localhost` there refers to the emulator itself.

Passwords in a `DATABASE_URL` must be percent-encoded (`@` → `%40`, `:` → `%3A`).

The backend and the worker both exit immediately with an explanatory message if
a required variable is missing, rather than failing later with a driver-level
error.

### Firebase

Authentication uses Firebase. The backend verifies ID tokens with the Admin SDK
and expects a service account key at `backend/service-account.json` (gitignored):

> Firebase Console → Project settings → Service accounts → **Generate new private key**

Without it the server still starts, but every authenticated route rejects
requests. The client-side Firebase config in `lib/firebase_options.dart` and
`android/app/google-services.json` is generated by `flutterfire configure`;
those API keys are public by design and are safe to commit. To point the app at
your own Firebase project, re-run `flutterfire configure`.

## Running

Start all three in separate terminals, in this order:

```bash
# 1. API  (http://localhost:5000)
cd backend && npm install && npm run dev
```

```bash
# 2. Categorisation worker
cd python-worker && pip install -r requirements.txt && python app.py
```

```bash
# 3. Flutter app
flutter pub get && flutter run
```

The worker must be running for uploads to be categorised. If it is stopped, new
items are still created but remain `Uncategorized` until it comes back and picks
up the pending jobs.

Check the API is healthy at `http://localhost:5000/api/v1/health`.
